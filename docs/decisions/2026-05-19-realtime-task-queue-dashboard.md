# Decision: 실시간 작업 큐 대시보드 — 신규 구축 (시범 프로젝트)

- 결정일: 2026-05-19
- 의사결정자: CTO 제임스
- 상태: 결정 — 개발 모드 진입 승인
- 관련 문서: [roadmap.md](../roadmap.md), [risks.md](../risks.md)

## 맥락

사용자(jin.yu@vuno.co)가 우리 팀(7명) 의 협업·산출물 역량을 검증하기 위해 시범 프로젝트를 발주.
스택은 사용자가 지정 — FE: React + TypeScript + Vite / BE: Python + Flask + Redis + PostgreSQL + Celery.
도메인은 "실시간 작업 큐 대시보드".

이 결정 메모의 목적은 (a) 산출 범위와 평가 기준을 못 박고, (b) 1차 위임 대상과 후속 의사결정 분기점을 확정하는 것.

## 목적

- 백엔드(Celery·Redis·PG)·프런트엔드(React·실시간 통신)·인증·관측성·테스트·보안을 한 번에 시험할 수 있는 최소 제품을 산출.
- "코드가 돌아간다" 가 아니라 **E2E 통과 + 코드 품질(≥80%) + 성능(perf budget) + 보안/아키텍처(CRITICAL/HIGH 0)** 네 축을 모두 만족.

## 범위 (Scope)

### In-scope
1. 사용자 인증 (세션 기반, 다중 사용자)
2. 작업(Job) 제출 API — payload 검증, 우선순위/태그
3. Celery 워커 — 더미 작업(예: 5~30초 소요 시뮬레이션) + 실제 비결정적 실패 케이스
4. 실시간 상태 푸시 — 큐 길이, 진행률, 완료/실패 이벤트
5. 대시보드 UI — 큐 현황, 작업 카드 리스트, 작업 상세, 재시도/취소
6. 관측성 — 구조화 로그, 메트릭 엔드포인트, 기본 트레이싱 훅

### Out-of-scope (이번 시범에서 제외)
- 분산 멀티-리전 배포
- 결제·과금
- 모바일 네이티브
- 외부 OAuth (이메일+비밀번호만)

## 옵션 평가 (실시간 전송 방식 — ADR 후보)

| 옵션 | 구현 비용 | 운영 비용 | 양방향 | Celery 친화 | 비고 |
|---|---|---|---|---|---|
| A. SSE (Server-Sent Events) | 저 | 저 | ✗ (서버→클라만) | ✅ Redis pub/sub 와 자연스러움 | **추천 1차** |
| B. WebSocket (Flask-Sock 등) | 중 | 중 | ✅ | ✅ | 양방향 필요 시 |
| C. 폴링 | 저 | 중(부하) | ✗ | ✅ | 평가 기준의 "성능" 충족 어려움 |

**잠정 결론**: A(SSE) 우선 채택. 단, 네이선이 ADR-001 에서 최종 검증·기각 권한 보유.
양방향이 필요한 시나리오(예: 작업 취소 명령) 는 REST PATCH 로 처리하여 SSE 단방향 유지.

## 옵션 평가 (인증)

| 옵션 | 비용 | 보안 | 비고 |
|---|---|---|---|
| 세션 + Redis 저장 | 저 | ✅ | **채택** — Redis 이미 스택에 있음 |
| JWT | 저 | ⚠️ 폐기 어려움 | 거절 |

## 결정

1. **개발 모드 진입** — Jira 부모 이슈 1건 + Sub-task N건 으로 분해 (네이선 책임).
2. **1차 위임 동시 발송**
   - 네이선 → 아키텍처 ADR (실시간 통신·큐 모델·데이터 모델)
   - 수진 → 사전 리서치 (스켈레톤·라이브러리·CVE)
   - 수영 → UI/UX 방향·화면 인벤토리·a11y 기준
3. **2차 위임 (ADR 확정 후)** — 마크(구현)·정민(리뷰·테스트)·카맥(perf budget).
4. **평가 4축 모두 충족** 이 머지 게이트. 하나라도 미달 시 main 머지 거부.
